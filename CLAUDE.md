## Что это
Веб-приложение для симуляционного обучения биостатистике с ИИ: студент/специалист проходит кейс из 10 шагов
(ситуация → данные с ошибками → типы переменных → вопрос → метод → код R/Python → интерпретация →
проверка ошибки ИИ → дебрифинг → завершение). Пилотное исследование «до/после».

  но есть профиль «имя/фамилия» (видят студент и преподаватель, в выгрузки не попадает).

## Код (ai-biostat/)
- `app/main.py` — FastAPI: /api/login, /logout, /me, PUT /profile, GET/PUT /state (весь прогресс JSON, отсюда
  таблица attempts), /events (tutor_open, code_run, step_enter), /diagnostic, /disputes, /disputes/mine,
  /teacher/overview, /teacher/disputes/{id} (решение обязательно с обоснованием), /teacher/confirm, /teacher/export/{attempts|events|diagnostics|disputes}.csv (только коды, разделитель ;, BOM для Excel).
- `app/db.py` — SQLite, схема + миграция колонок first_name/last_name; журнал audit.
- `app/security.py` — pbkdf2, токены сессий (cookie aib_session, httponly; AIB_SECURE_COOKIE=1 на сервере).
- `frontend/` — фронтенд: **React 18 + TypeScript + Vite**, i18n через react-i18next. Пользователь просил
  придерживаться **SOLID и ООП**. Сборка (`npm run build` в frontend/) кладёт готовые файлы в `static/`, и **они
  коммитятся в git**: сервер (t3.micro, 1 ГБ) ничего не собирает, автообновление работает как раньше.
  После любой правки фронтенда: `cd frontend && npm test && npm run build`, затем коммитить и `static/`.
  **Версия** — поле version в frontend/package.json, видна возле логотипа (v0.3.1; при наведении — время сборки).
  Перед каждой выкладкой поднимать: исправления — 0.3.1→0.3.2, новые возможности — 0.3.x→0.4.0.
  Git: **никаких веток**, всё коммитить и пушить сразу в main (push = деплой).
  Структура: `core/` (HttpClient, Store), `api/` (классы AuthApi, ProgressApi, ResearchApi, DisputesApi, TeacherApi),
  `domain/` (CaseDefinition — схема кейса как данные; scoring/ — StepScorer-стратегии + CaseScorer, DebriefBuilder;
  GradeScale; code/CodeRunner — интерфейс, сейчас SimulatedCodeRunner, Pyodide/WebR будут новой реализацией;
  diagnostic/), `cases/` (case21 + CaseRegistry — новый кейс = файл описания + строка в реестре),
  `app/` (AppStore — состояние и все его изменения; services/ — SessionService, AutoSaver (600 мс), ResearchTracker,
  LanguageService, ProgressSerializer; container.ts — точка сборки зависимостей), `screens/` (экраны и 10 шагов
  плеера), `ui/`. Формат state на сервере не менялся (совместим со старой версией). Тесты логики: `npm test` (vitest).
  Экраны: login, diag (демо 4 вопроса), diagres, home, player (кейс 21), profile, teacher (Проверка / Редактор
  кейсов — макет / Диагностика — макет / Участники и выгрузка).
- `tools/participants.py`, `deploy/setup.sh` (идемпотентная установка: apt, Caddy, venv, systemd, cron backup,
  /usr/local/bin/aib-participants), `tests/test_api.py` (5 тестов, `python -m pytest -q`).

## Ключевые продуктовые решения (от методиста и автора — соблюдать)
- 10 шагов кейса; баллы 100: данные 10, типы 10, вопрос 5, метод 20 (2 попытки, −5), подготовка данных 5 +
  расчёт 10 (готовый код после 3 неудачных запусков −5), интерпретация 25 (рубрика), ловушка ИИ 15.
- Баллы во время кейса скрыты, только в дебрифинге. Ответы шагов 1–4 редактируются до прохождения шага 5.
- Оценка ИИ «предварительная» до решения преподавателя; кнопка «Оспорить оценку» → статус «оспаривается», не блокирует.
- Шкала: 100 баллов + буква (A 95+, A− 90, B+ 85, B 80, B− 75, C+ 70, C 65, C− 60, D+ 55, D 50, FX 25, F 0).
- Студент: шаблон кода с пропусками, вывод ≥40 слов. Специалист: пишет код сам, ≥60 слов.
  Студенты — 4 базовых кейса (1, 4, 21, 23); специалисты — все 5 (+22).
- Код выполняется в браузере: Pyodide (Python) и WebR (R). На телефоне — только Python, рекомендовать ПК.
- ИИ-репетитор в пилоте — ссылка на авторский GPT
  https://chatgpt.com/g/g-6927183a0bb48191a49dda7e8525f334-biostatistika-p-ninen-zhi-repetitory ;
  в системе считаем только переходы (event tutor_open). Репетитор заблокирован на шагах 4, 7, 8.
- Языки RU/KZ/EN (казахский — основной для студентов!). Термины: RU/KZ + международное в скобках.
- Учебные данные: плашка «Учебные данные. Данные смоделированы специально…» на каждом экране кейса;
  без реальных стран/городов/организаций («Учебная территория», «Регион A–D»); названия болезней сохраняем.
- Стиль: строгий светлый академический, без тёмной темы, без рейтинга группы. Логотип/брендбук — до декабря.
- Диагностика: 2 параллельных варианта по 20 вопросов (вход/итог).
